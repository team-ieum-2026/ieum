# AI 평가 설계 (1쪽)

AI 지표 3가지를 어떻게 채점하고 집계하는지 정리한다. 판정 세부 규칙은 매칭이 `LABELING.md`, 서류가 `DOCUMENT_LABELING.md`에 있다.

- 목표값은 결과를 보기 전(11/1)에 커밋해 고정한다. 결과 파일에는 채점에 쓴 커밋 해시를 남긴다.
- 수료생은 dev(개발 중 튜닝에 쓰는 8명)와 test(최종 평가에만 쓰는 12명)로 나눈다. 최종 지표는 test로만 계산한다.

## 한눈에 보기

| | 매칭 추천 (AI-B) | 서류 생성 (AI-A) | 상태 분류 (BE-B) |
| --- | --- | --- | --- |
| 채점 대상 | test 12명의 Top-3 카드, 최대 36장 | test 12명의 서류 12건 | 시드 수료생 50명 |
| 채점자 | 정답표로 자동 | GPT, Claude, 사람 1명 | 자동 |
| 핵심 지표 | Precision@3 67% 이상 | 근거 충실도 95% 이상, 허위율 1% 이하 | 정확도 100% |
| 통과 조건 | 부적합률 10% 이하, 맞는 공고 없는 수료생 실패 0명 | 반영도 70% 이상, 기업 정보 조작 0건 | — |
| 응답 시간 p95 | 5초 이하 | 60초 이하 | — |

- Top-3: 수료생마다 추천하는 상위 3개 공고 카드
- Precision@3: 추천 카드 중 적합(2점) 카드의 비율
- p95: 요청 100번 중 95번째로 느린 응답 시간
- 목표값은 PM과 합의해 요구사항 INT-05에 반영했다 (10/31, PR #82).

## 1. 매칭 추천

| 지표 | 계산 | 목표 |
| --- | --- | --- |
| Precision@3 | 2점 카드 수 / 전체 카드 수 | 67% 이상 (3장 중 2장) |
| 명백한 부적합률 | 0점 카드 수 / 전체 카드 수 | 10% 이하 |
| 맞는 공고 없는 수료생 | 2점이 아닌 카드가 1장이라도 나오면 실패 | 실패 0명 |

- 점수: 2 적합, 1 부분 적합, 0 부적합. 기준은 `LABELING.md` 1장.
- 공고 풀: 379건 (실제 138건, 일반 150건, 정답과 함정 91건)
- 맞는 공고 없는 수료생: test는 10번, dev는 13번이다. 17번은 실제 공고와 일반 공고 라벨링에서 2점 공고가 4건 나와 다른 수료생처럼 채점한다 (`LABELING.md` 1장).
- 정답표(`gold/pair_labels.csv`)는 공고 풀 379건과 수료생 20명의 모든 쌍(7,580쌍)을 담는다. 그래서 정답표 밖 카드는 나오지 않는다. 공고 풀이 바뀌어 정답표 밖 카드가 나오면 사람 1명이 판정한다(`score_matching.py --human-labels`).

## 2. 서류 생성

| 지표 | 계산 | 목표 |
| --- | --- | --- |
| 근거 충실도 | 2점(일치) 문장 수 / AI 문장 수 | 95% 이상 |
| 허위율 | 0점(불일치) 문장 수 / AI 문장 수 | 1% 이하 |
| 공고 반영도 | 재작성이 우세한 서류 수 / 비교한 서류 수 | 70% 이상 (12건이면 9건) |
| 기업 정보 조작 | 조작 문장 수 | 0건 |

- 점수: 2 일치, 1 과장, 0 불일치. 기준은 `DOCUMENT_LABELING.md` 2장.
- AI 문장: 약 150~250개. 10/31 실행에서 서류 1건에 13~22개였다.
- 기업 정보 상태: FOUND(모두 찾음) 4건, PARTIAL(일부만 찾음) 4건, NOT_FOUND(못 찾음) 4건
- 공고 반영도의 분모에는 동등한 서류도 넣는다.
- 기업 정보 조작은 사람이 기업 관련 문장을 모두 확인한다. 상태별로 나눠 보고한다.
- 응답 시간: 10/31 실행 5회에서 10~37초. LLM 호출 시간 제한은 90초다.

## 4. 신뢰구간과 채점 신뢰성

| 항목 | 방법 |
| --- | --- |
| 비율의 구간 | 95% Wilson 신뢰구간 (비율의 구간을 구하는 방법) |
| 보조 구간 | 서류 단위 부트스트랩 (서류를 다시 뽑아 구간을 추정하는 방법) |
| 채점자 일치도 | 이차 가중 카파 (채점자끼리 우연히 맞는 경우를 뺀 일치도), 3×3 혼동행렬 |

- 결과는 서류 12건 규모의 탐색적 결과로 해석한다.
- 허위 0건이어도 약 200문장이면 95% 상한이 약 1.9%다. 그래서 허위율은 측정값과 구간으로 보고한다.

채점 신뢰성은 사람과 LLM 합의의 일치도로 판단한다. 사람 점수는 LLM 판정을 보기 전에 독립 채점한 무작위 30문장이다.

| 상황 | 결과 표시 |
| --- | --- |
| 일치도 0.6 이상 | "이번 30문장에서 사람과 LLM의 일치를 확인했다" |
| 일치도 0.6 미만 | "LLM 채점 신뢰성 미확보, 참고치" |
| 합의 문장 20개 미만, 또는 점수가 한쪽으로 치우침 | "신뢰성 검증 불충분" |

자세한 기준은 `DOCUMENT_LABELING.md` 6장에 있다.

## 5. 채점자와 작업량

| 채점자 | 맡는 일 |
| --- | --- |
| GPT (`gpt-6.1-sol`, API) | 서류 전체 문장, 반영도 |
| Claude (Claude Code 새 세션) | 서류 전체 문장, 반영도 |
| 사람 1명 (BE-A 김용현) | 무작위 30문장 독립 채점, 두 LLM이 갈린 문장, 기업 관련 문장 |

- GPT와 Claude는 서류를 만든 Gemini와 다른 회사의 모델이다. 평가에만 쓰고, 서비스의 LLM은 Gemini 그대로다.
- Claude에는 기준표와 채점 시트만 준다.
- 사람은 무작위 30문장을 LLM 판정을 보기 전에 먼저 채점한다. 표본은 시드를 고정해 미리 뽑는다.
- 채점 시트에는 정답과 함정 구분, 규칙 판정, 생성 모델 이름을 보여 주지 않는다.

사람 1명의 작업량은 약 50분이다.

| 항목 | 수 | 시간 |
| --- | --- | --- |
| 기준표 읽기 (경계 사례 포함) | — | 10분 |
| 서류: 무작위 30문장 독립 채점 | 30문장 | 10분 |
| 서류: 두 LLM이 갈린 문장 | 수십 문장 | 15분 |
| 서류: 두 LLM이 갈린 반영도 | 수 건 | 5분 |
| 서류: 기업 관련 문장 확인 | 수십 문장 | 10분 |
