# AI 평가 설계 (1쪽)

지표 3가지의 채점 대상, 채점자, 기준, 집계 방법을 정리한다. 판정 세부 규칙은 매칭이 `LABELING.md`, 서류가 `DOCUMENT_LABELING.md`에 있다. 매칭 루브릭 코드는 `rubric.py`다.

목표값은 결과를 보기 전(11/1)에 커밋해 고정한다. 결과 파일에는 채점에 쓴 커밋 해시를 남긴다.

수료생은 dev(개발 중 튜닝에 쓰는 8명)와 test(최종 평가에만 쓰는 12명)로 나눈다. 최종 지표는 test로만 계산한다.

아래 표의 Top-3는 수료생마다 추천하는 상위 3개 공고 카드다. 응답 시간 p95는 요청 100번 중 95번째로 느린 응답 시간이다.

## 지표 3가지

| | 매칭 추천 (AI-B) | 서류 생성 (AI-A) | 상태 분류 (BE-B) |
| --- | --- | --- | --- |
| 채점 대상 | test 12명의 Top-3 카드, 최대 36장 | test 12명의 서류 12건, AI 문장 약 150~250개 | 시드 수료생 50명 |
| 채점자 | 정답표로 자동. 정답표에 없는 카드는 사람 1명 | GPT와 Claude가 전체, 사람 1명이 일부 독립 채점 | 자동 |
| 점수 | 2 적합, 1 부분, 0 부적합 | 2 일치, 1 과장, 0 불일치 | 정답 여부 |
| 핵심 지표 | Precision@3 | 근거 충실도, 허위율 | 정확도 |
| 통과 조건 | 명백한 부적합률 | 공고 반영도, 기업 정보 조작 | — |
| 목표 (제안) | Precision@3 67% 이상, 부적합률 10% 이하 | 충실도 95% 이상, 허위율 1% 이하, 반영도 70% 이상, 조작 0건 | 100% |
| 응답 시간 p95 | 5초 이하 | 60초 이하 | — |

### 매칭 추천

공고 풀은 379건이다. 실제 공고 138건, 일반 공고 150건, 정답과 함정 공고 91건으로 이루어진다.

Precision@3는 추천 카드 중 2점(적합) 카드의 비율이다. 목표 67%는 카드 3장 중 2장이 적합하다는 뜻이다. 명백한 부적합률은 0점 카드의 비율이다.

맞는 공고가 없는 10번 수료생(test)은 따로 본다. 2점이 아닌 카드가 1장이라도 나오면 실패다.

정답표(`gold/pair_labels.csv`)에 없는 카드는 사람 1명이 루브릭으로 판정한다. 약 10~20장으로 예상한다.

함께 보고할 항목: 실제 공고만 본 결과와 전체 결과, 흔한 직무와 드문 직무, Top-3 카드의 출처 분포, 무작위 추천 대비 차이, dev 8명 점수(튜닝에 쓴 수료생이라고 밝힘).

### 서류 생성

서류는 test 12명에게 공고 1건씩 만든다. 기업 정보 상태는 FOUND(모두 찾음) 4건, PARTIAL(일부만 찾음) 4건, NOT_FOUND(못 찾음) 4건으로 배정한다. 10/31 실행에서는 서류 1건에 AI 문장이 13~22개였다.

근거 충실도는 2점 문장의 비율이고, 허위율은 0점 문장의 비율이다. 분모는 모두 AI 문장 수다. 문체나 맞춤법을 고친 것은 과장으로 보지 않는다.

공고 반영도는 원본과 재작성 자기소개서 중 어느 쪽이 공고에 더 맞는지 비교한다. 목표는 재작성이 우세한 서류의 비율이고, 분모에는 동등한 서류도 넣는다. 12건을 모두 비교하면 70%는 9건 이상이다.

기업 정보 조작은 서류 12건 전체에서 사람이 기업 관련 문장을 모두 확인한다. 기업 정보 상태별로 나눠 보고한다.

함께 보고할 항목: 과장률(1점 문장의 비율), 제외율(`excludedSentenceCount`를 전체 생성 문장 수로 나눈 값), 자료가 충실한 수료생과 부실한 수료생의 차이, 서류별 점수 분포, 반영도의 원본 우세와 동등 비율, 기업 정보 상태별 조작률.

응답 시간은 10/31 실행 5회에서 10~37초였다. LLM 호출 시간 제한은 90초다.

### 상태 분류

시드의 `student_status`와 같으면 정답이다. 규칙 기반이라 틀리면 버그로 보고 고친다. 그래서 목표가 100%다.

## 신뢰구간과 신뢰성

모든 비율은 95% Wilson 신뢰구간(비율의 구간을 구하는 방법)과 함께 보고한다. 문장은 서류별로 묶여 있어서, 서류 단위 부트스트랩(서류를 다시 뽑아 구간을 추정하는 방법) 구간을 보조로 낸다. 결과는 서류 12건 규모의 탐색적 결과로 해석한다.

허위 0건이어도 약 200문장이면 95% 상한이 약 1.9%다. 그래서 허위율은 측정값과 구간으로 보고한다.

채점 신뢰성은 이차 가중 카파(채점자끼리 우연히 맞는 경우를 뺀 일치도)와 3×3 혼동행렬로 보인다. 비교 대상은 GPT와 Claude 사이, 사람과 각 LLM 사이, 사람과 LLM 합의 사이다. 사람 점수는 LLM 판정을 보기 전에 독립 채점한 무작위 30문장이다.

사람과 LLM 합의의 일치도가 0.6보다 낮으면 결과에 "LLM 채점 신뢰성 미확보, 참고치"라고 표시한다. 합의 문장이 20개보다 적거나 점수가 한쪽으로 치우치면 "신뢰성 검증 불충분"이라고 적는다. 자세한 기준은 `DOCUMENT_LABELING.md` 6장에 있다.

## 개발 중 지표 (dev 8명, 자동)

- 매칭: 정답률, 함정 진입률(우선), 미판정 비율. 추천 카드별 점수와 어긋난 조건까지 공개한다.
- 서류: 근거 검증 통과율, 이유별 제외율, 기업 정보 조작 자동 검사, 의미 판정, 공고 반영도. 의미 판정은 최종과 같은 기준표로 GPT 하나가 채점한다.
- test 12명은 최종 전에 1~2회만 실행하고 점수만 본다.

## 채점자

서류는 LLM 2개가 전체를 따로 채점한다. GPT(`gpt-6.1-sol`)는 API로 부른다. Claude는 Claude Code 새 세션에서 기준표와 채점 시트만 주고 채점한다.

두 모델은 서류를 만든 Gemini와 다른 회사의 모델이다. 평가에만 쓰고, 서비스의 LLM은 Gemini 그대로다.

사람 1명의 작업량은 약 1시간으로 예상한다.

| 항목 | 수 | 시간 |
| --- | --- | --- |
| 기준표 읽기 (경계 사례 포함) | — | 10분 |
| 매칭: 정답표에 없는 카드 | 약 10~20장 | 10분 |
| 서류: 무작위 30문장 독립 채점 | 30문장 | 10분 |
| 서류: 두 LLM이 갈린 문장 | 수십 문장 | 15분 |
| 서류: 두 LLM이 갈린 반영도 | 수 건 | 5분 |
| 서류: 기업 관련 문장 확인 | 수십 문장 | 10분 |

무작위 30문장은 LLM 판정을 보기 전에 먼저 채점한다. 표본은 시드를 고정해 미리 뽑는다.

채점 시트에는 정답과 함정 구분, 규칙 판정, 생성 모델 이름을 보여 주지 않는다.
