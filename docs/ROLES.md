각자 돌리는 AI가 가장 먼저 읽는 파일이라, 협업 규칙은 여기에 적습니다. Codex · Cursor는 `AGENTS.md`를 읽고, Claude Code는 `CLAUDE.md`에 넣은 `@AGENTS.md` 한 줄로 같은 규칙을 읽습니다.

- 자기 담당 폴더 밖의 파일은 수정하지 않는다.
- 위 표의 공용 파일을 수정해야 하면, 작업 전에 멈추고 사용자에게 "파일 주인에게 확인했나요?"를 먼저 묻는다.
- 라이브러리 추가, DB 스키마 · JSON 스키마 · API 형식 변경은 사용자 확인 없이 하지 않는다.
- PR 설명에 공용 파일 수정 여부를 적는다.

수료생 50명 시드는 PM이 만들어 레포에 넣어 두었습니다(`db/seed.sql`). 모두 이 파일 하나로 같은 데이터를 씁니다. 모든 이름과 수치는 모의 데이터입니다.

- **평가용**은 일부러 섞었습니다: 직무(BE · FE · AI · 풀스택 · 데이터), 역할 기록이 구체적인 사람과 모호한 사람, README가 충실한 사람과 짧은 사람, 맞는 공고가 없을 사람(게임 · 임베디드 · 부산 희망).

- **공고**는 시드에 넣지 않고 BE-A 배치로 실제 공고를 받습니다. 시드에는 배치 전 개발용 임시 공고 3건과, 지난 응답 이력용 마감 공고 12건만 있습니다(`source = DEV_SEED`).

- **주인공**은 통합 기간(11/2~11/4)에 id 1 자리에 넣습니다. 팀원 한 명의 실제 교육 결과물을 가명으로 쓰고(본인 동의), 그 자료로 시연 흐름을 다시 확인합니다.
